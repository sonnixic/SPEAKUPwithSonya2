# SPEAK UP! with Sonya 🎀 — обновлённый первый урок

Публикация через GitHub Pages: см. [пошаговую инструкцию без команд](GITHUB-PAGES.md). Для Pages используйте чистый архив speak-up-github-pages.zip; комнаты требуют отдельного Node.js-хостинга.

Этот проект переработан на прежнем стеке React + TypeScript + Tailwind CSS. Сохранены палитра, персонажи, навигация, Teacher Mode и таймер. Все аудиозадания, аудиокнопки, записи и зависимости от озвучки удалены. Произношение отрабатывает преподаватель по видеосвязи.

## 1. Провести локальный урок сегодня

Самый простой способ: дважды нажмите **Открыть урок.html**. Это готовая самостоятельная страница, установка зависимостей не нужна. Она открывается в браузере и работает без интернета. Для комнат используйте способ из следующего раздела.

Нажмите **LET'S START!**, впишите имена двух учениц, выберите разные аватары и нажмите **Начать с алфавита**. В этом режиме преподаватель демонстрирует экран и нажимает кнопки за учениц.

Если браузер ограничивает локальные HTML-файлы или сохранение данных, запустите **Открыть урок.cmd** и откройте **http://127.0.0.1:4174**. Оставьте окно сервера открытым. Если вкладка открылась раньше сервера, обновите её.

Для CMD требуется Node.js 24 или новее. На текущем компьютере файл также находит встроенный Node из Codex. На другом компьютере установите Node.js с [официального сайта](https://nodejs.org/en/download).

## 2. Управление уроком

- Этапы переключаются кнопками слева, упражнения — вкладками под заголовком.
- **Следующий вопрос** меняет вопрос внутри упражнения. **Дальше / пропустить** позволяет двигаться дальше без отметки выполнения.
- **Отметить выполнение** сохраняет прогресс; **Повторить** даёт новую попытку.
- Переключайте имена учениц или **Together** в верхней полосе. В Teacher Mode есть рекомендация распределения практики между ученицами.
- **Teacher Mode** справа вверху открывает цели, объяснения, ответы, ошибки и дополнительную практику. Закрывается крестиком. При демонстрации экрана ученицы видят всё открытое на вашем компьютере, поэтому закрывайте панель перед самостоятельным ответом.
- Таймер запускается кнопкой **▶**, пауза — **Ⅱ**, сброс — **↻**. Он не переключает задания автоматически.
- В переводах принимаются полные формы и указанные сокращения. Вариант вне готового ключа не объявляется ошибочным: его проверяет преподаватель. Свободные описания, устное чтение и собственные предложения оцениваются вручную.

План: **0–12** алфавит; **12–20** чтение; **20–32** местоимения и to be; **32–42** практика; **42–52** текст; **52–60** парное задание и итоги. Всего **60 минут**.

В последнем разделе доступны печать памятки, сохранение PDF средствами браузера, скачивание TXT и пять домашних предложений с проверкой. Готовая **Памятка.pdf** лежит рядом с проектом.

Локально сохраняются имена, аватары, текущий раздел и вопрос, отметки выполнения, остаток таймера. После обновления локальный таймер на паузе. Незавершённые ответы внутри упражнения вводятся заново. Сохранение зависит от localStorage браузера; это только личная локальная сессия, не обмен между компьютерами.

## 3. Backend и учебная комната

В проект включён настоящий backend на **Node.js + Server-Sent Events (SSE)**. Внешняя база, Supabase, аккаунты учениц и сервисные ключи не нужны. Сайт и API работают на одном адресе; отдельно подключать frontend к backend не требуется.

Запустите **Открыть урок.cmd**. Альтернатива: откройте терминал в папке проекта и выполните `node server.cjs`, затем откройте http://127.0.0.1:4174.

1. Преподаватель нажимает **Создать комнату**, вводит имя и подтверждает создание.
2. Появляется случайный восьмисимвольный код комнаты. Он действует 24 часа.
3. Ученицы открывают этот же сайт на своих устройствах, нажимают **Join room**, вводят код и имя, выбирают аватар. Регистрация, email и пароль не нужны.
4. В комнате максимум две ученицы. Этап, упражнение, вопрос и таймер меняет преподаватель; проверка прав выполняется на сервере.
5. Ученицы отправляют ответы со своих устройств. Преподаватель видит две отдельные карточки и статус подключения.
6. Преподаватель может **Принять**, **Повторить**, **Открыть правильный ответ**, **Разрешить видеть ответы друг друга** и **Дать повторную попытку**.
7. В парной игре первая ученица выбирает местоимение, вторая форму; во втором раунде роли меняются. Это исключение для выбора входного элемента игры, а не право менять этап.
8. При обновлении страницы сохраняется доступ к своей роли и ответам. При временном разрыве связи клиент переподключается и получает актуальное состояние сервера. Используйте тот же браузер и не удаляйте его данные во время урока.
9. **Выйти из комнаты** у ученицы освобождает её место и отзывает прежний доступ. **Закрыть комнату** у преподавателя закрывает её для всех.
10. **Новое занятие / новая комната** закрывает прежнюю комнату и позволяет создать новую с другим кодом.

**Важно:** адрес `127.0.0.1` работает только на вашем компьютере. Отправлять его ученицам через интернет нельзя. Для разных компьютеров через интернет нужен опубликованный HTTPS-адрес, как описано ниже.

## 4. Опубликовать для занятия через интернет

Публичная публикация пока **не выполнена**: нужны ваш аккаунт хостинга и выбранное место хранения состояния. Сценарий с тремя браузерными сессиями проверен на настоящем локальном сервере; доступ с трёх удалённых компьютеров через интернет не проверялся.

Можно использовать любой хостинг, который запускает постоянный Node.js-процесс и поддерживает SSE. Ниже пример для Render по его [официальной инструкции](https://render.com/docs/deploy-node-express-app).

1. Создайте аккаунты GitHub и Render самостоятельно.
2. Создайте GitHub-репозиторий и загрузите содержимое папки проекта. **Не загружайте** `node_modules`, `.runtime`, `.env` и файлы с данными комнат. Для публикации нужны исходники, `package.json`, конфигурация, `server.cjs`, `build-standalone.cjs` и остальные файлы проекта. Можно загрузить готовый `dist` тоже, но сервер будет использовать свежую сборку.
3. В Render выберите **New → Web Service**, подключите репозиторий. Корневая папка сервиса должна содержать `package.json`.
4. Runtime: **Node**. Build Command: `npm install && npm run build`. Start Command: `npm start`.
5. Добавьте переменные окружения: **HOST = 0.0.0.0**, **NODE_VERSION = 24**. Порт **PORT** Render задаёт сам. Проверка здоровья: `/api/health`.
6. Для сохранения комнат после перезапуска или публикации новой версии задайте **DATA_DIR** на постоянную папку сервера. Например, при подключённом диске с mount path `/var/data`: **DATA_DIR = /var/data/sonya**. Достаточно одного экземпляра сервера. Несколько экземпляров с разными файлами состояния не поддерживаются.
7. Если постоянного диска нет, комнаты сохраняются в `.runtime` текущего экземпляра. На хостингах с временной файловой системой эти данные могут исчезнуть после перезапуска или новой публикации. В Render постоянные диски доступны для платных сервисов; решение о хостинге и тарифе принимаете вы. Можно использовать собственный уже имеющийся сервер с постоянной папкой. [Документация хранения](https://render.com/docs/disks).
8. Нажмите **Deploy**. Дождитесь успешной сборки и откройте выданный HTTPS-адрес. Он должен показать урок, а адрес `/api/health` — `ok: true`.
9. На опубликованном сайте создайте **новую** комнату. Локальные комнаты не переносятся автоматически.
10. Проверьте опубликованный адрес в трёх браузерных сессиях: преподаватель и две ученицы. Убедитесь, что переключение вопроса и ответы синхронизируются.

Никакие ключи Supabase или секретные сервисные ключи вставлять в браузер не нужно. Для этой реализации backend — включённый Node.js-сервер. Если выбранный хостинг поддерживает только статические HTML-файлы, локальный урок откроется, но комнаты работать не будут: требуется **Web Service**, а не Static Site.

## 5. Что отправить ученицам

После публикации и создания комнаты нажмите **Скопировать приглашение**. Ученицам отправьте:

> Откройте ссылку: https://ВАШ-САЙТ/?room=КОДКОМНАТЫ. Введите своё имя и выберите аватар. Если ссылка не подставила код, нажмите Join room и введите КОДКОМНАТЫ. Регистрация не нужна. Видеосвязь с преподавателем остаётся в привычной программе.

Не отправляйте доступ преподавателя или файлы состояния сервера. Достаточно ссылки и кода комнаты.

## 6. Защита и хранение

Коды комнат генерируются криптографически случайно (40 бит); доступ к роли подтверждается индивидуальным случайным токеном (256 бит). Сервер хранит хэш токена, проверяет роль при каждом изменении и фильтрует ответы до отправки клиенту. До разрешения преподавателя ученица получает только собственные ответы. Число попыток входа ограничено: 12 за 10 минут на IP; создание комнат — 4 в минуту. Комнаты истекают через 24 часа. Токен своей сессии хранится только в браузере для восстановления, не передаётся по URL.

Собираются только введённое имя, аватар, роль и учебные ответы. Код — приглашение: передавайте его только участницам. Для интернет-публикации используйте HTTPS. Общая синхронизация идёт через сервер и SSE; localStorage не используется для обмена между устройствами.

Состояние хранится в файле `rooms.json` внутри **DATA_DIR** либо `.runtime`. Файл недоступен через публичный HTTP-сервер. Сохраняйте эту папку при обслуживании сервера; не публикуйте её в GitHub или в архиве проекта.

## 7. Проверки и разработка

Сборка: `npm install`, затем `npm run build`. Проверка TypeScript входит в сборку. Сервер: `npm start`. Для разработки: сначала `npm start` в одном терминале, затем `npm run dev` в другом; Vite перенаправляет `/api` на localhost:4174.

Проверены 26 учебных экранов, британские R/O/Z, полные и сокращённые ответы, текст и перевод по кнопке, домашняя проверка, печать, скачивание, таймер, Teacher Mode, сохранение имён и самостоятельный HTML-файл. На backend проверены три независимые браузерные сессии, одновременные ответы, запрет изменения этапа ученицей, запрет доступа без токена, предел комнаты, сокрытие чужих ответов, повторная попытка, обновление страницы, временное отключение и оба раунда парной игры.

Ограничения браузера: печать/PDF и скачивание выполняются браузером; восстановление своей сессии зависит от сохранности его данных. Кнопка копирования может требовать HTTPS; если браузер её блокирует, скопируйте URL и код вручную. Видеосвязь и устная оценка выполняются преподавателем вне сайта.
